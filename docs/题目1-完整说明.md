## 一、题目要什么（原文拆解）

> 利用 opencv/yolo 识别下列**红、蓝、红蓝相间**三种不同的物块，并且能够通过 **ros2 话题输出**
> 物块的**种类、长度以及距离摄像头中心点的坐标**。（实际误差不能超过 **3cm**）
> （PS：识别一个面就可以，可以从网上寻找图片并下载，重点是精准度）
>
> 加分项：如果我的参照点与摄像头的中心有一定的偏移，程序能够通过**调整偏移量**实现精准的定位；
> 能够进行 **yolo 调优**。
>
> **识别帧率和输出话题频率 >= 60hz**

拆成可验收的条目：

| # | 要求 | 怎么算达标 |
|---|---|---|
| 1 | 识别三种物块 | 三种都能分类正确 |
| 2 | 输出**种类** | 话题里能看出是哪种 |
| 3 | 输出**长度** | 要求 3cm 精度 → 必须给**厘米/米**，不能给像素 |
| 4 | 输出**距摄像头中心点的坐标** | 相对**相机光心**的 x/y/z（米），不是像素坐标 |
| 5 | **通过 ROS2 话题** | 不能只 print，要 `publish`，`ros2 topic echo` 能看到 |
| 6 | 误差 **≤3cm** | 和独立真值比 |
| 7 | 帧率/话题频率 **≥60Hz** | `ros2 topic hz` 显示 ≥60 |
| 8 | 加分①：偏移补偿 | 挪动参照点后仍准 |
| 9 | 加分②：YOLO 调优 | 可选 |

**题目明确允许用图片**（"可以从网上寻找图片并下载"）→ 不需要真实相机。

**为什么分成三层**：出错时能分清是哪一层的问题。
算法错了就调 `task1_detect.py`（开个窗口改参数立刻见效）；
通信错了就查话题名/QoS。混在一起时你分不清"没输出"是阈值不对还是收不到图。

**三个交付形态**（都在 `src/`）：Python 节点、C++ 节点（`vision_task1`）、自定义消息（`vision_task1_interfaces`）。

## 三、算法流程（6 步）

```
图像
 ├─1─ 畸变校正（有标定参数时）           cv2.undistort
 ├─2─ BGR → HSV，按阈值分出红/蓝掩膜      cv2.inRange（红色要两段！）
 ├─3─ 形态学：各色 OPEN 去噪 → 合并后 CLOSE 补缝
 ├─4─ 找轮廓，按面积过滤
 ├─5─ 对每个轮廓：
 │      · 在【轮廓内部】统计红蓝像素 → 分类（纯色 / 上下分层 / 左右相邻）
 │      · 量像素边长（√面积 − 偏置）
 │      · 针孔模型 → 距离 Z 与坐标 X/Y
 └─6─ 画框、打印、发布
```

### 每一步为什么这么做

**① 畸变校正**：真实镜头边缘会"弯"，物块在画面边上时像素宽度量不准。
标定一次拿到 `dist` 填进参数区，代码自动校正。仿真相机畸变为 0，可跳过。

**② 红色必须分两段**：HSV 里红色跨 0°/180° 两端。
只写 `[0, 10]` 会漏掉靠近 179 的那半边红。所以：
```python
mask_red = inRange(hsv, (0, s, v), (8, 255, 255)) | \
           inRange(hsv, (172, s, v), (179, 255, 255))
```

**③ 形态学顺序很关键**：

- 先对**每种颜色各自** `OPEN`（腐蚀后膨胀）→ 去掉孤立噪点
- **再合并两色**，对**合并后的掩膜**做 `CLOSE`（膨胀后腐蚀）→ 补上红蓝之间的暗缝

> ⚠️ **这是踩过的坑**：一开始把 `CLOSE` 写在"每种颜色各自"的处理里，
> 结果完全没用 —— 每种颜色本身就是完整的半块，自己跟自己 CLOSE 没有任何效果。
> 而红蓝相间的物块在分界处因为模糊会混成一条"紫红色"窄带（既不属于红也不属于蓝），
> 掩膜在这里断开 → **一个物块被拆成"纯红"+"纯蓝"两个轮廓**：
> 类别判错，而且每半个的高度只有一半 → **距离直接偏 30%**。
> 这个 bug 是拿 324 张带真值的图集跑评测才发现的（单看一张图看不出来，因为那张渲染图的分界处没有模糊带）。

**④ 面积过滤**：门限 = `max(绝对下限 200px, 0.05% × 图像面积)`。
只用绝对像素的话，高分辨率手机照片里 243px 的杂色斑会被当成物块（算出 2 米远）；
只用比例的话，小图上的小物块会被误杀。**两者取大最稳。**

**⑤ 分类判据**（三种情况）：

```python
if r_red >= 0.80:                 # 单一颜色绝对多数
    return "red"
if r_blue >= 0.80:
    return "blue"
if r_red >= 0.18 and r_blue >= 0.18:   # 两色都有 → 查是不是"分层/相邻"
    axis, first_is_red, purity, balance, ... = _layer_split(...)
    if purity >= 0.85 and balance >= 0.25:
        return "red_blue"
return 占优的那一色
```

`_layer_split` 会自动找分界线，而且**水平和垂直两个方向都试**：

- `axis="h"` 上下分层（上红下蓝）
- `axis="v"` 左右相邻（**立方体两个相邻的面**，比如左面红、右面蓝）

> ⚠️ **这也是踩过的坑**：老版本只扫水平线，遇到"左红面 + 右蓝面"就完全判不出来，
> 会退化成纯红或纯蓝。题目只说"红蓝相间"，没说必须上下排列。

判据里两个量的含义：

- `purity` = 1 − 错配像素占比。越接近 1 说明这条线把两种颜色分得越干净。
  **纯红/纯蓝的物块因为缺少另一种颜色凑不出两半，purity 上不去 → 判不出 red_blue**（这是它天然的防误判机制）
- `balance` = 两半面积的均衡度。防止"一整块红 + 边上一小条蓝"被当成相间

**⑥ 像素边长怎么量**：

| 方法 | 说明 |
|---|---|
| `bbox` | 外接矩形的 (宽+高)/2 |
| `minAreaRect` | 最小外接旋转矩形（原来用的） |
| `front_face` | `approxPolyDP` 找正方形面 |
| **`area`（默认）** | **√(轮廓面积) − `edge_bias_px`** |

实测结论：四种估计**都系统性偏大**（掩膜外扩），但 `√面积` 的偏差最稳定
（恒为 +1.0~1.1px，四个样本一致），减掉 `edge_bias_px=1.0` 之后 Z 误差全部 <0.5cm。
`bbox/minAreaRect` 会被轮廓噪声撑大，小目标上尤其明显。

**⑦ 针孔模型（像素 → 米）**：

```
Z = fy · W_real / edge_px          相似三角形：物体越大/离得越近，占的像素越多
X = (u − cx) · Z / fx              像素偏右多少 → 实际偏右多少米
Y = (v − cy) · Z / fy              像素偏下多少 → 实际偏下多少米
```

坐标系约定：**相机光学坐标系**（x 右、y 下、z 前），这也是 ROS2 相机系的标准约定。

## 四、60Hz 怎么做到

**核心：识别和发布必须解耦。**

```python
# 后台线程：不断取最新帧 → 识别 → 存进 self.latest
def worker_loop(self):
    while rclpy.ok():
        frame = 取最新帧()
        results = detect(frame)
        with self.lock:
            self.latest = results

# 定时器（固定 60Hz）：把最新结果发出去
def publish_tick(self):
    for r in self.latest:
        self.pub.publish(消息)
```

识别一帧 1~2ms，但**绝不能"识别一次发一次"** —— 否则话题频率被识别速度绑死。
现在识别慢一点没关系，话题频率永远 60Hz。

**其他提速手段**（按收益排序）：降分辨率（640×480 → 320×240）、
ROI 裁剪、C++ 版本编译 Release（`-DCMAKE_BUILD_TYPE=Release`，默认 Debug 会慢好几倍）。

## 五、参数怎么调

所有参数集中在 `py/task1_detect.py` 顶部的 `P` 字典，改完立即生效（不用重编译）：

| 参数 | 什么时候改 |
|---|---|
| `real_edge_m` | **必须拿尺子量物块后填**，它决定所有绝对精度 |
| `fx/fy/cx/cy/dist` | 标定后填；用 Gazebo 虚拟相机则从 `/camera_info` 自动获取 |
| 红/蓝 HSV 阈值 | 换灯光、换相机、换物块材质后重调（用 `py/tune_hsv.py` 拖滑条） |
| `close_kernel` | 红蓝两块补不上缝就加大（但也别太大，免得把相邻物块连起来） |
| `min_area_px/ratio` | 有噪点被误检就加大；小物块漏检就减小 |
| `offset_x_m/offset_y_m` | **加分项①**：测出参照点与光心的偏移后填这里 |
| `measure` | 边长取法，默认 `area`（实测最准） |

> 调 HSV 的方法：`python3 py/tune_hsv.py --image 你的图.png`，拖滑条看掩膜，满意了按 `s` 保存。

## 六、排查手册

| 症状 | 原因 | 解决 |
|---|---|---|
| `ros2: command not found` | 没 source | `source /opt/ros/humble/setup.bash` |
| `Package 'xxx' not found` | 没 source 工作区 / 没编译 | `source install/setup.bash`；`colcon build --symlink-install` |
| 订阅不到图像 | **QoS 不匹配**（最常见） | 相机发 `best_effort`，订阅要用 `qos_profile_sensor_data` |
| `cv_bridge` 导入报 `_ARRAY_API not found` | numpy 2.x 与 cv_bridge 冲突 | **别用 cv_bridge**，自己转（见 `task1_node.py` 的 `imgmsg_to_numpy`） |
| 红蓝相间判成纯色 | 两块之间的缝没补上 | 加大 `close_kernel`（默认 13） |
| 距离总是偏小 | 物块斜着放/离画面中心太远 | 让物块**正对镜头**；或接受 `tan²θ` 的离轴误差 |
| 合成图很准、真实照片很烂 | 阈值是按合成图调的 | 用 `tune_hsv.py` 按实拍照片重调 |
| Gazebo 相机一渲染就崩 | WSL 硬件渲染问题 | 用软件渲染（launch 里已默认） |

## 七、怎么一步步做完这道题

1. **跑通算法**：`python3 py/task1_detect.py --src samples/first.png --show`
2. **跑通话题**：`ros2 launch vision_task1_sim camera_scene.launch.py` + `ros2 topic echo /block_info`
3. **测频率**：`ros2 topic hz /block_info`（≥60）
4. **测精度（合成图）**：`python3 py/eval_synth.py --samples samples_synth`
5. **测精度（独立真值）**：`python3 src/vision_task1_sim/scripts/verify_sim.py`
6. **（可选，最有说服力）拿真实照片验证**：按 `targets/README-拍摄说明.md` 拍几张，
   量出屏幕上物块的真实边长填进 `real_edge_m`，再和卷尺读数对比
7. **加分项①**：标定得到 `cx, cy`，与图像中心比较得出偏移量，填 `offset_x_m/offset_y_m`
8. **（可选）加分项②**：YOLO 调优
9. **提交**：按根目录 `README.md` 的提交清单
