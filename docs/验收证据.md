## 2. Gazebo 虚拟相机（真值来自仿真器物理位姿）

```bash
# 终端 A
ros2 launch vision_task1_sim camera_scene.launch.py
# 终端 B
python3 src/vision_task1_sim/scripts/verify_sim.py
```

| 类别 | 样本 | 平均\|X误差\| | 平均\|Y误差\| | 平均\|Z误差\| | 最大\|Z误差\| | ≤3cm |
|---|---|---|---|---|---|---|
| red | 710 | 0.49 cm | 0.03 cm | 2.12 cm | 2.12 cm | **100%** |
| blue | 710 | 0.42 cm | 0.03 cm | 2.11 cm | 2.11 cm | **100%** |
| red_blue | 710 | 0.05 cm | 0.05 cm | **0.25 cm** | 0.25 cm | **100%** |

### 为什么这里的真值比合成图集"硬"

- 识别结果是从**像素**反推的
- 真值来自 `/gazebo/model_states` —— 仿真器里物体的**真实物理位姿**
- 两者**毫无关系**：这是真正独立的外部检验，不是"自己出题自己答"

### red/blue 那 2.1cm 误差的几何解释

物块**离开画面中心**时，图像上会有轻微放大（`sec²θ` 效应），用正轴公式算就会把 Z 算小：

```
δZ ≈ Z · tan²θ          θ = atan(横向偏移 / 距离)
```

- `block_red/blue`：横向偏 9cm、距离 40cm → θ≈12.7°，tan²θ≈0.051
  → 0.40m × 0.051 ≈ **2.0cm**（实测 2.12cm ✓）
- `block_red_blue`：在光轴上（θ=0）→ 误差只剩 **0.25cm** ✓

**结论：仍然全部达标。** 想进一步压到 0.2cm 可以加离轴修正
`Z_true ≈ Z_measured·(1 + tan²θ)`，但它只对**真三维物块**成立、对平面合成图不成立，
所以没有默认加进算法。

## 3. 话题与频率

```bash
ros2 topic hz /block_info
```

| 指标 | 实测 |
|---|---|
| `/block_info` 频率 | **179.98 ≈ 180 Hz**（3 个方块 × 60Hz） |
| 达标线 | ≥60 Hz ✅ |
| 发布机制 | 识别在独立线程，发布用 60Hz 定时器 → **两者解耦** |

**为什么话题频率能稳在 60Hz 以上**：识别一帧要 1~2ms，但绝不能"识别一次发一次"，
否则话题频率就被识别速度绑死。代码里把两件事拆开：

- 后台线程：取最新帧 → 识别 → 存进 `self.latest`
- 定时器（固定 60Hz）：把 `self.latest` 发出去

识别慢一点没关系，话题频率永远是 60Hz。**这是 60Hz 达标的关键设计。**

## 4. 相机内参与画面

```bash
ros2 topic echo /camera/camera_info --once
```

| 参数 | 值 | 说明 |
|---|---|---|
| 图像尺寸 | 640 × 480 | |
| `fx` / `fy` | **554.2547** | = 320 / tan(30°)，插件按水平视场 60° 自动算出 |
| `cx` / `cy` | 320 / 240 | 光心正好在图像中心 |
| 畸变 `d` | 全 0 | 仿真相机无畸变 |

**这是虚拟相机路线最大的好处：内参由插件直接发布，不需要用棋盘格标定。**

相机实际拍到的画面见 `results/sim_camera_view.png`（三个方块都**正对镜头**，
图像里都是正方形 —— 这是相似三角形测距公式成立的前提）。

相机实际出图频率：**12.2 fps**。这是 **WSL 软件光栅化 640×480 的上限**，
不是算法或代码的问题（算法 1.8ms/帧）。真实相机或原生 Ubuntu 上不存在这个限制。

## 5. 手机实拍照片（鲁棒性证据，不是精度验收）

`samples/phone_16cm.jpg` —— 用手机拍电脑屏幕上的三个物块（距离约 16cm，Redmi Note 12 Turbo）。

```bash
python3 py/task1_detect.py --src samples/phone_16cm.jpg
```

结果：**3 个目标全部识别正确**（red / blue / red_blue，红蓝相间置信度 98.9%）。

这张图证明了：**算法能处理真实相机的脏数据**（噪声、摩尔纹、反光、色偏）。

但它**不能用于精度验收**，原因：
1. 图里是立体斜视（能看到三个面），轮廓 ≠ 棱长
2. 屏幕上三个方块物理尺寸不同，真值不成立

**阈值提醒**：手机拍屏幕后饱和度中位数从 255 掉到 94、明度掉到 129，
照抄合成图的阈值会漏检 —— 真实照片必须用 `py/tune_hsv.py` 重调。
