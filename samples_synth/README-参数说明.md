# 合成测试图集 · 完整参数说明

> 这就是"**图片 + 所需的所有参数**"：每张图的物块类别、真实距离、真实偏移、真实边长全部已知，
> 所以能算出**真实误差**（而不是靠感觉说"应该挺准"）。

---

## 一、这套图是怎么来的

```bash
cd vision_task1/py
python3 make_test_images.py --out ../samples_synth
```

生成器按**针孔相机模型**把物块投影到图上，**它在生成时就记录了真值**，所以参数的来源是可靠的（不是事后反推的）。

规模：**324 张图**（3 种类别 × 4 个距离 × 3×3 个偏移 × 3 档光照），另有 324 个同名 `.txt`（每张图单独的真值）。

---

## 二、相机参数（整套图共用）

| 参数 | 值 | 含义 |
|---|---|---|
| 图像尺寸 | **640 × 480** | 宽 × 高（像素） |
| `fx` | **600.0** | 焦距 x（像素）—— 像素↔米的换算系数 |
| `fy` | **600.0** | 焦距 y（像素） |
| `cx` | **320.0** | 光心 x（像素）= 图像宽 / 2 |
| `cy` | **240.0** | 光心 y（像素）= 图像高 / 2 |
| 畸变系数 `dist` | **全 0** | 合成图没有镜头畸变 |
| 物块真实边长 | **0.05 m（5.0 cm）** | 三种类别都一样 |

> 这 5 个数就是 `task1_detect.py` 顶部参数区要填的东西。**填对了才可能过 3cm。**

---

## 三、真值表 `ground_truth.csv`

每行对应一张图。列的含义：

| 列名 | 含义 | 单位 |
|---|---|---|
| `file` | 图片文件名 | — |
| `block_class` | **真实类别**：`red` / `blue` / `red_blue` | — |
| `distance_m` | **真实距离 Z**（相机到物块） | 米 |
| `x_m` / `y_m` | **真实横向/纵向偏移**（相对光心，右为正、下为正） | 米 |
| `real_edge_m` | **真实边长** | 米 |
| `edge_px` | 物块在图上的**真实像素边长** | 像素 |
| `u_px` / `v_px` | 物块中心的**真实像素坐标** | 像素 |
| `light` | 生成时用的亮度系数（0.7 / 1.0 / 1.3，模拟明暗变化） | — |
| `noise_sigma` | 加的高斯噪声强度 | — |
| `jpeg_quality` | JPEG 压缩质量（92，模拟真实照片的压缩损失） | — |
| `flip_layers` | 红蓝相间块是否上下翻转（1 = 上蓝下红） | — |

文件名本身也把参数编码进去了，例如：
`synth_red_blue_d0800mm_xp0040_ym0040_L070.png` = 红蓝相间 / 距离 800mm / x 偏 +40mm / y 偏 −40mm / 亮度 0.7

## 四、怎么用它验证你的算法

```bash
cd vision_task1/py

# ① 单张精度的"真实值"快照
#    红蓝相间块里，红的一半像素有没有被算进去？
python3 task1_detect.py --src ../samples_synth/synth_red_blue_d0300mm_xp0000_yp0000_L100.png

# ② 跑全套 324 张，出误差统计（分类准确率 + Z/X/Y 误差 + 按距离分组）
python3 eval_synth.py --samples ../samples_synth
```

## 六、这套图能证明什么、不能证明什么

**能证明**
- 你的公式、单位换算、阈值、分类逻辑**写对了没有**（300+ 样本的统计结果）
- 你的算法**在什么距离范围内**能满足 3cm
- 改代码以后有没有变差（回归测试）

**不能证明**
- 真实相机的**镜头畸变、传感器噪声、白平衡、光照不均**对精度的影响
  —— 因为这套图是用**同一个针孔模型**生成的，属于"自己出题自己答"
- 所以：**最终 3cm 的验收，仍然要拍真实照片**（手机拍正对的物块 + 卷尺量距离）

**正确用法**：合成图当"实验室"，把算法调到最好；再用真实照片做"实战验收"。
